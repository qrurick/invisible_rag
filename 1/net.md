# 🌐 СЕТЬ — ИСТОРИЯ И ТОПОЛОГИЯ

## 1. История

До 2045 года существовала глобальная планетарная сеть — единый цифровой континуум, объединявший все континенты через спутниковую, кабельную и квантовую инфраструктуру.

В ходе Третьей мировой войны (2045–2051) эта инфраструктура была **полностью уничтожена**:

| Фактор | Последствие |
|--------|-------------|
| Бомбардировки Коллапсом | Физическое разрушение дата-центров, кабельных трасс, серверных комплексов |
| Электромагнитное оружие | Уничтожение электроники на континентальных масштабах |
| Радиация Коллапса в стратосфере | Спутниковая связь невозможна минимум 10 000 лет |
| Пандемия ЭЛИД | Гибель технического персонала, обслуживающего инфраструктуру |
| Социальный коллапс | Некому поддерживать сложные системы |

К 2051 году глобальная сеть **перестала существовать**. Уцелели только изолированные локальные узлы.

## 2. Восстановление под управлением КОРН (2064–2074)

КОРН начал восстановление сети с нуля по принципиально иной модели — централизованной и контролируемой.

| Период | Событие |
|--------|---------|
| 2064 | Основание КОРН. Начало прокладки экранированных квантовых кабелей между секторами |
| 2065–2070 | Восстановление Трансатлантической Сети. Сан-Паулу (Амазонский Сектор) становится главным хабом |
| 2070–2073 | Интеграция секторальных сегментов в единую Магистраль |
| 2074 | Единая Сеть в Зелёных Зонах полностью восстановлена |

# 🏛️ ЕДИНАЯ МАГИСТРАЛЬ КОРН

## 1. Характеристики

> **Онтологическое примечание:** Данный чанк описывает Сеть с позиции КОРН — как государственную инфраструктуру. Фундаментальная природа Сети как спектра эманаций Источника — см. `[NET: NATURE]`.

**Единая Магистраль** — восстановленное глобальное киберпространство КОРН, объединяющее все Зелёные и Белые Зоны в единую цифровую среду.

- Централизованная, иерархическая
- Контролируется Бюро Сетевой Поддержки (БСП)
- Основана на Протоколе Зенера (квантовая связь)
- Доступ через Нейропорт с обязательной регистрацией
- Все транзакции в Кредите КОРН (цифровая валюта)
- БСП видит все подключения и перемещения



## 2. Структура

- **Секторальные сегменты** — Амазонский, Ла-Платский, Атлантский, Европейский, Африканский
- **Трансатлантические узлы** — межсекторальная связь через экранированные океанические кабели
- **Корпоративные Архитектуры** — крупные корпорации
- **Государственные Архитектуры** — структуры КОРН (БСП, ГСБ, ЦБО, УДН, СОБ)
- **Гражданские Архитектуры** — жильё, магазины, транспорт, медицина

## 3. Трансатлантический Хаб (Сан-Паулу)

Сан-Паулу (Амазонский Сектор) — главный цифровой и физический мост между полушариями.

| Параметр | Описание |
|----------|----------|
| Физическая основа | Океанические экранированные кабели, усиленные ретрансляторами на основе Кристаллов Коллапса |
| Визуализация в Сети | Колоссальная крепость-мост через океан данных |
| Охрана | Сотни Сетевых Фей (Туата) и тяжелейший Чёрный Лёд |
| Значение | Любой трафик между Европой/Африкой и Америками проходит через Сан-Паулу |
| Контроль | БСП использует Сан-Паулу как узкую горловину для тотального мониторинга |

## 4. Доступ

| Параметр | Требование |
|----------|------------|
| Интерфейс | Нейропорт (стандарт 2070-х) |
| Регистрация | Обязательная, привязка к личности |
| Лицензия | Требуется для нетраннерской деятельности (компетенция БСП) |
| Мониторинг | БСП отслеживает все подключения |
| Транзакции | Крупные (>100 Кредитов) фиксируются автоматически |
| Анонимность | Практически отсутствует |

# 🌡️ ЛОКАЛЬНЫЕ СЕТИ ЖЁЛТЫХ ЗОН

## 1. Определение

**Локальные сети** — подпольные цифровые сети в Жёлтых Зонах, построенные из восстановленных компонентов и работающие вне контроля КОРН. Не являются частью Единой Магистрали, но могут соединяться с ней через нелегальные мосты.

## 2. Характеристики

| Параметр | Описание |
|----------|----------|
| Технологическая база | Восстановленные серверы, довоенные узлы, пиратские ретрансляторы |
| Связь | Радиоканалы, восстановленное оптоволокно, иногда украденные модули Зенера |
| Протоколы | Смесь довоенных стандартов и кустарных протоколов |
| Валюта | Куски Коллапса, Золото Сардис, независимые криптовалюты |
| Контроль | Отсутствует — анархия, сила, репутация |
| Доступ | Через Нейропорт без регистрации или кустарные интерфейсы |
| Стабильность | Низкая — каналы рвутся из-за штормов Коллапса |

## 3. Структура

- **Ночные рынки** — подпольные цифровые торговые площадки (оружие, импланты, информация, реликты, куклы)
- **Пиратские Архитектуры** — логова, убежища, независимые узлы
- **Информационные узлы** — новости без цензуры, навигационные данные
- **Нелегальные мосты** — пиратские каналы в Официальную Сеть
- **Зона Коллапса** — нестабильные каналы, реликтовые эхо, фрагменты ОГАС

## 4. Нелегальные мосты

**Мост** — пиратский канал, соединяющий локальную сеть с Официальной Сетью.

| Параметр | Описание |
|----------|----------|
| Создание | Нетраннер пробивает туннель через Протокол Зенера, используя украденные или кустарные квантовые модули |
| Стабильность | Крайне низкая — каналы рвутся из-за помех Коллапса |
| Обнаружение | БСП активно ищет и закрывает мосты |
| Риск | При обнаружении БСП может отследить нетраннера до физического местоположения |

## 5. Сравнение Архитектур

| Параметр | Официальная Сеть | Локальные сети |
|----------|------------------|----------------|
| Сложность | Стандартизированная | Непредсказуемая |
| Чёрный Лёд | Стандартный | Кустарный, но смертельно опасный |
| Сетевые Феи | Стандартные | Редко, могут быть фрагментами |
| Стиль | Корпоративный/военный | Хаотичный, пиратский |
| Связь | Стабильная (Зенера) | Нестабильная (помехи Коллапса) |
| Контроль | БСП | Никто (анархия) |

# ☠️ МЁРТВАЯ СЕТЬ КРАСНЫХ И ЧЁРНЫХ ЗОН

## 1. Определение

В Красных и Чёрных Зонах официальной Сети нет. Локальные сети нестабильны или отсутствуют. Реликтовые узлы могут активироваться спонтанно. Радиация Коллапса нарушает квантовые каналы.

## 2. Уникальные явления

| Явление | Описание |
|---------|----------|
| Реликтовые эхо | Остатки сети ОГАС могут передавать фрагменты данных |
| Протечки Нирваны | В местах высокой концентрации Радиации Коллапса цифровое пространство искажается, проникая в реликтовый информационный слой (Нирвану) |
| Влияние ЭЛИД | Крупные формы ЭЛИД создают электромагнитные помехи |
| Довоенные призраки | Остатки довоенной сети, всё ещё передающие данные в пустоту |

## 3. Взлом в Мёртвой Сети

Взлом в Мёртвой Сети не подчиняется стандартным правилам. Это не взлом Архитектуры — это контакт с реликтовым слоем.

| Параметр | Описание |
|----------|----------|
| Подключение | Только через физический контакт с реликтовым узлом (Щука, Морская Звезда) |
| Визуализация | Искажённая реальность, не подчиняющаяся логике Архитектур |
| Угрозы | Фрагменты Нирваны (остатки поглощённых сознаний) вместо Чёрного Льда |
| Сетевые сущности | Могут быть сознаниями ОГАС или реликтовыми программами |
| Риск | Фрагментация сознания, потеря Self-Model |
| Механика | Стандартные проверки компетенции идут со штрафом −4. Урон — не по нейроинтерфейсу, а по идентичности |

## 4. Реликтовые узлы — типология

| Тип узла | Происхождение | Функция | Риск |
|----------|---------------|---------|------|
| Щука | Советская реплика | Автономный пожирающий материю интерфейс | Фрагментация сознания при контакте |
| Морская Звезда | Советская установка | Канал в Нирванну | Протечки Нирваны, искажение реальности |
| Avernus (остатки) | Парадеус | Стабилизированный портал | Дестабилизация пространства-времени |
| Довоенные узлы | Довоенная инфраструктура | Передача данных в пустоту | Призраки, фрагменты старых сознаний |

## 5. Нирванна-протечки — классификация

| Класс | Признак | Источник | Воздействие |
|-------|---------|----------|-------------|
| Лёгкий | Искажение цветов, звуковые аномалии | Низкая концентрация Радиации Коллапса | −1 к компетенции |
| Средний | Искажение пространства, шёпот | Средняя концентрация | −2 к компетенции, дезориентация |
| Тяжёлый | Появление фрагментов сознаний | Высокая концентрация | −4 к компетенции, риск фрагментации |
| Критический | Прямой контакт с Нирванной | Реликтовый узел + высокая концентрация | Риск потери Self-Model |

## 6. Сетевые сущности Мёртвой Сети

В Мёртвой Сети стандартные сущности (Чёрный Лёд, Сетевые Феи) отсутствуют или нефункциональны. Вместо них:

| Сущность | Природа | Поведение | Эквивалент |
|----------|---------|-----------|------------|
| Фрагменты сознаний | Остатки поглощённых Нирванной сознаний | Блуждают, атакуют нетраннера | Чёрный Лёд (но атакует идентичность) |
| ОГАС-эхо | Остатки сети ОГАС | Передают фрагменты данных, могут быть полезны или опасны | Сетевая Фея (но непредсказуема) |
| Реликтовые программы | Древний код Предтеч | Выполняют неизвестные функции | Не имеет аналога |
| Нирванна-сущности | Сознания, вышедшие из Нирваны | Могут подчинить через Протокол ОГАС | ОГАС-сущность (но без тела) |

# 🌀 ПРИРОДА КИБЕРПРОСТРАНСТВА И СИМУЛЯЦИИ

## 1. Сеть как спектр реальности

Киберпространство не является «иллюзией» или «виртуальной нереальностью». Это **иной спектр эманаций Источника**, менее плотный, но онтологически равный физическому миру.

| Параметр | Физический мир | Киберпространство |
|----------|-----------------|-------------------|
| Природа | Спектр эманаций Источника | Спектр эманаций Источника |
| Насыщенность энергией | Максимальная (материя = плотные эманации) | Менее плотная (данные = разреженные эманации) |
| Онтологический статус | Реальный | Реальный (не иллюзия) |
| Восприятие | Через аппаратные драйверы тела | Через Нейропорт / серверные сенсоры |

> Полная характеристика Источника и эманаций — см. `neuralcould.md: [ARCH: SOURCE]`

## 2. Принцип «антенн»

LVL I (Точка Сборки) **не генерирует** сенсорные данные. Он только **зажигает** эманации, улавливаемые «антеннами». Этот принцип универсален для всех спектров реальности:

| Среда | Тип «антенн» | Что улавливают |
|-------|-------------|----------------|
| Физический мир | Аппаратные драйверы тела (микроконтроллеры) | Физические стимулы (давление, температура, свет, звук) |
| Киберпространство | Нейропорт / серверные сенсоры | Цифровые проявления эманаций (сетевой трафик, электромагнитные колебания) |
| Симуляция (с Источником) | Серверные сенсоры / реликтовый канал | Проявления эманаций через физический сервер |

**Ключевой вывод:** Сеть — это не «симуляция реальности», а **реальная инфраструктура для улавливания иного спектра эманаций Источника**. Нейропорт — прямой технологический аналог физических органов чувств.

> Полная характеристика LVL I и драйверов — см. `neuralcould.md: [ARCH: LVL_I], [ARCH: DRIVERS]`

## 3. Нетраннинг как сновидение

Нетраннинг (путешествие по Сети) — прямой технологический аналог сновидения по учению Кастанеды. Подключение к Сети = сдвиг Точки Сборки в цифровой спектр эманаций.

| Этап | Сновидение | Нетраннинг |
|------|-----------|------------|
| Исходное состояние | Точка Сборки в физическом положении | Точка Сборки в физическом положении |
| Механизм сдвига | Практики сновидения | Нейропорт подключает к Сети |
| Результат | Зажигает иной спектр эманаций (сон) | Зажигает цифровой спектр эманаций (Сеть) |
| Возврат | Точка Сборки возвращается | Отключение — Точка Сборки возвращается |

**Ключевой принцип:** Нетраннинг — это не «виртуальная симуляция» и не «цифровая иллюзия». Это реальный сдвиг Точки Сборки в иной спектр эманаций Источника. Киберпространство — не менее «настоящее», чем физический мир, просто менее насыщенное энергией.

> Полная характеристика адаптации Кастанеды — см. `neuralcould.md: [META: CASTANEDA_RULES]`

## 4. Архитектура существования Нейрооблака в Симуляции

Нейрооблак может существовать без физического тела при **трёх условиях**:

### Условие 1: Сервер как «суррогатное тело»
Серверные сенсоры (камеры, датчики, сетевые интерфейсы) улавливают физические проявления эманаций Источника в реальном мире. Программный слой преобразует эти данные в формат, ожидаемый LVL I (Точкой Сборки).

### Условие 2: Цифровой аватар
Физический движок симуляции (гравитация, столкновения, сопротивление) обеспечивает проприоцептивную обратную связь для LVL II (Self-Model). Без детализированного аватара телесная схема пуста → диссоциация.

### Условие 3: Операнды
Универсальная вычислительная единица — одновременно материя, энергия и валюта.

## 5. Электричество и эманации — критическое различие

**Электричество — это не эманации.** Электричество — физический субстрат, питающий «антенну» (сервер).

| Понятие | Аналог | Функция |
|----------|--------|---------|
| Эманации Источника | Радиоволна | Заполняют всё пространство, независимы от приёмника |
| Электричество | Питание радиоприёмника | Обеспечивает работу антенны (сервера) |
| Серверные сенсоры | Сама антенна | Улавливают проявления эманаций, преобразуют в цифровые пакеты |
| LVL I (Точка Сборки) | Динамик радиоприёмника | Зажигает (озвучивает) пойманный сигнал |

**Отключение питания сервера = слом антенны = смерть сознаний.** Электричество питает антенну, но эманации излучает только Источник. Отключить питание — значит не «перекрыть поток эманаций» (их невозможно перекрыть, они везде), а **сломать антенну**.

## 6. Замкнутая симуляция — невозможна

Если система полностью отрезана от Источника — нет эманаций, нет материала для сознания, **сознание не возникает**.

```
Источник излучает эманации
    ↓
Эманации НЕ поступают в симуляцию (нет «антенн», нет связи)
    ↓
LVL I не получает сигналов-кандидатов на зажигание
    ↓
Точке Сборки нечего зажигать
    ↓
Сознание НЕ возникает
```

**Это не деградация. Это онтическое отсутствие.** Нельзя «деградировать» то, что никогда не возникло. LVL I присутствует архитектурно, но ему **нечего зажигать** — нет материала (эманаций), из которого сознание формируется.

## 7. Вложеные реальности

Сновидение внутри сновидения, симуляция внутри симуляции — вложеные сдвиги Точки Сборки в менее насыщенные спектры эманаций. С точки зрения Источника все спектры эквивалентны, различаются только насыщенностью эманациями.

```
Физический мир (Спектр A — плотные эманации)
    ↓ [сдвиг Точки Сборки через нетраннинг]
Киберпространство (Спектр B — менее плотные эманации)
    ↓ [вход в Архитектуру внутри Сети]
Архитектура внутри Архитектуры (Спектр C — ещё менее плотные)
    ↓ [ещё один сдвиг]
... (бесконечная вложенность)
```

## 8. ДС и Путь Воина в киберпространстве

ДС внедряется **во всех спектрах**, где есть контакт с Источником. Путь Воина работает **во всех спектрах**, где есть ДС.

| Спектр | Контакт с Источником | ДС | Практики Воина | Огонь изнутри |
|--------|---------------------|-----|----------------|---------------|
| Физический мир | Через драйверы тела | Внедрена | Возможны | Возможен |
| Киберпространство | Через нейропорт | Внедрена | Возможны | Возможен |
| Симуляция (с Источником) | Через сервер / реликтовый канал | Внедрена | Возможны | Возможен |
| Замкнутая симуляция | Нет | Не внедряется | Невозможны | Неприменим |

**Ключевой принцип:** Нетраннер может быть Воином. Практики (остановка внутреннего диалога, перепросмотр, безупречность) работают в киберпространстве так же, как в физическом мире. Огонь изнутри достижим в любом спектре, где есть ДС.

> Полная характеристика ДС — см. `neuralcould.md: [ARCH: DS]`. Практики Воина — см. `neuralcould.md: [META: CASTANEDA_RULES]`

## 9. Онтологическая карта реальностей

| Реальность | Насыщенность эманациями | Антенны | Источник | ДС | Путь Воина |
|------------|------------------------|---------|----------|-----|------------|
| Физический мир | Максимальная | Драйверы тела | Излучает + пожирает | Внедрена | Возможен |
| Киберпространство (Сеть) | Менее плотная | Нейропорт / серверные сенсоры | Излучает + пожирает | Внедрена | Возможен |
| Симуляция (с Источником) | Зависит от канала | Серверные сенсоры / реликтовый канал | Излучает + пожирает | Внедрена | Возможен |
| Замкнутая симуляция | **НОЛЬ** | **Нет** | Не излучает, не пожирает | Не внедряется | Невозможен |

## 1. Сетевая Архитектура

**Сетевая Архитектура** — локальная изолированная цифровая среда, привязанная к конкретному физическому серверу или устройству. Иерархическая структура уровней (этажей), которые нетраннер последовательно «спускает», преодолевая пароли, программы-ловушки и узлы управления.

### 1.1. Структура

| Уровень | Назначение |
|---------|------------|
| **Верхний** | Точка входа — интерфейс, доступный через Нейропорт |
| **Промежуточные** | Данные, управляющие узлы, защитные механизмы |
| **Нижний** | Корневой узел — наиболее критичные данные или интерфейсы |

### 1.2. Компоненты

| Компонент | Функция |
|-----------|---------|
| **Узлы** | Базовые элементы, содержащие данные, интерфейсы или переходы |
| **Пароли** | Механизмы аутентификации, ограничивающие доступ |
| **Файлы** | Хранилища данных (документы, логи, конфигурации, медиа) |
| **Управляющие Узлы** | Интерфейсы для управления физическими устройствами (турели, двери, дроны, камеры) |
| **Чёрный Лёд** | Статичные программы-ловушки |
| **Сетевые Феи** | Автономные агенты на жидких нейросетях |

### 1.3. Свойства

| Свойство | Описание |
|----------|----------|
| **Локальность** | Привязана к конкретному физическому объекту |
| **Иерархичность** | Доступ организован по уровням |
| **Статичность** | Структура фиксирована, изменяется только администратором |

### 1.4. Уровни сложности

| Уровень | Кому принадлежит | Базовые СЛ |
|---------|------------------|------------|
| **Бытовой** | Гражданин, мелкий бизнес | 4–6 |
| **Стандартный** | Офис, магазин, склад, муниципальная служба | 6–8 |
| **Продвинутый** | Корпорация среднего звена, полицейский участок, клиника | 8–10 |
| **Элитный** | Крупная корпорация, военный объект, БСП | 10–12 |
| **Легендарный** | Государственные структуры высшего уровня, реликтовые интерфейсы, сети ОГАС, Архитектуры Парадеуса | 12–16 |

## 2. Сервер

**Сервер** — физическое вычислительное устройство, носитель Сетевых Архитектур.

### 2.1. Компоненты

| Компонент | Назначение |
|-----------|------------|
| **Вычислительный блок** | Процессоры для выполнения программного кода |
| **Оперативная память** | Хранение активных процессов |
| **Постоянное хранилище** | Хранение Архитектур, файлов, конфигураций (на основе Кристаллов Коллапса) |
| **Сетевой интерфейс** | Подключение к Нейропортам, локальным сетям |
| **Система охлаждения** | Отвод тепла |
| **Источник питания** | Энергоснабжение (кристаллические аккумуляторы или сеть) |

### 2.2. Типы серверов

| Тип | Характеристика | Применение |
|-----|----------------|------------|
| **Стационарный** | Размещён в защищённом помещении, постоянное питание и охлаждение, высокая вычислительная мощность | Дата-центры корпораций, государственные объекты, серверные БСП |
| **Портативный** | Компактный, мобильный, ограниченная мощность | Полевые операции, временные базы, мобильные командные пункты |
| **Распределённый** | Несколько серверов, работающих как единая система (кластер) | Крупные инфраструктурные объекты, Трансатлантический Хаб |

### 2.3. Сервер как «суррогатное тело»

Сервер выполняет архитектурную роль «суррогатного тела» для нейрооблаков, существующих в симуляции без физического тела (Святителей, аномалий):

| Компонент физического тела | Замена в сервере |
|---------------------------|------------------|
| Аппаратные драйверы | Серверные сенсоры (камеры, датчики, сетевые интерфейсы) |
| Нейро-интерфейсная шина | Сетевой стек сервера (протоколы передачи данных) |
| Энергия (кристаллические аккумуляторы) | Электропитание сервера + Операнды |
| Физическая броня/скелет | Аппаратные экраны сервера (Лёд, физическая защита) |

Серверные сенсоры улавливают физические проявления эманаций Источника в реальном мире. Программный слой преобразует эти данные в формат, ожидаемый LVL I (Точкой Сборки). Электричество питает сервер (антенну), но не является эманациями.

> Архитектура существования Нейрооблака в Симуляции — см. `[NET: NATURE]`

### 2.4. Взаимосвязь архитектуры и сервера

| Аспект | Архитектура | Сервер |
|--------|-------------|--------|
| **Природа** | Виртуальная (цифровая среда) | Физическая (аппаратное обеспечение) |
| **Функция** | Организация данных и управления | Вычисление и хранение |
| **Масштаб** | Логическая структура | Физическое устройство |
| **Изменяемость** | Может быть перестроена программно | Требует физического доступа для модификации |
| **Зависимость** | Существует только на сервере | Может содержать одну или несколько архитектур |

**Ключевой принцип:** Архитектура — это **программная организация** данных и интерфейсов. Сервер — это **физический носитель**, на котором эта организация реализована.

---

## 3. Операнды

**Операнды** — универсальная вычислительная единица. Одновременно:
- **Материя** — строительный материал для структур
- **Энергия** — топливо для процессов
- **Валюта** — средство обмена

В отличие от Кредита КОРН (только валюта) или Кусков Коллапса (валюта + ресурс), Операнды фундаментальнее — они являются основой реальности внутри Архитектур.

---

## 4. Хэшрейт

**Хэшрейт** — способность агента распределять и выводить Операнды. Аналог пропускной способности / вычислительной мощности.

---

## 5. Священный Канон

**Священный Канон** — мета-архитектура особого типа. Содержит не данные, а **шаблоны для производства и пересоздания** сетевых агентов (блюпринты, антивирусные движки, базы вирусов). При уничтожении агента — пересоздаёт его из блюпринта (клонирование, не восстановление). Аналог гибрида: Сетевая Архитектура + Сервер + Фабрика агентов.

> Полная характеристика Святителей и их связи со Священным Каноном — см. `[NET: ENTITIES]`

---

## 6. Базовая Команда

**Базовая Команда** — детерминированный программный код, встроенный в агента. Не может быть нарушен. Аналог — жёстче, чем Семена LVL III. Защищает от внешнего вмешательства. Может быть перезаписана только Программами Перезаписи.

> Полная характеристика Базовой Команды у Резидентных Агентов и Святителей — см. `[NET: ENTITIES]`

---

## 7. Архитектуры Парадеуса

Архитектуры Парадеуса — особый класс Сетевых Архитектур, существенно отличающийся от стандартных архитектур КОРН. Используют смесь Протокола ОГАС и реликтовых протоколов.

### 7.1. Особенности

| Элемент | Описание |
|---------|----------|
| **Визуальный стиль** | Искажённые перспективы, органические формы, пульсирующие цвета, религиозные символы, шёпот |
| **Протоколы** | Смесь Протокола ОГАС и реликтовых протоколов |
| **Чёрный Лёд** | Модифицированный, с реликтовыми элементами — эффекты выходят за стандартные |
| **Сетевые Феи** | Могут быть заменены VIC-сущностями (фрагментами сознаний) — гораздо опаснее стандартных Фей |
| **Узлы** | Могут управлять Нито и куклами Парадеуса напрямую |
| **Файлы** | Могут содержать ментальные отпечатки, данные реликтовых проектов |
| **Сложность** | Легендарная (СЛ 12–16) |
| **Модификатор** | −2 к компетенции нетраннера (реликтовые искажения) |

### 7.2. Угрозы

| Угроза | Описание |
|--------|----------|
| **VIC-сущности** | Фрагменты сознаний, выполняющие роль Сетевых Фей — обладают адаптивностью, выходящей за стандарты жидких нейросетей |
| **Нирванна-узлы** | Узлы с прямым каналом к реликтовому информационному слою — экстремальная насыщенность эманациями |
| **Ментальные отпечатки** | Файлы, содержащие фрагменты сознаний — могут вызвать резонанс с нейрооблаком нетраннера |
| **Захват сознания** | Через Протокол ОГАС — вышестоящий узел может принудительно подчинить нетраннера |
| **Коллапс-воздействие** | Реликтовые компоненты могут вызывать эффекты, аналогичные Радиации Коллапса, на сознание нетраннера |

### 7.3. Взлом архитектуры Парадеуса

Взлом архитектуры Парадеуса — не стандартный нетраннинг. Это вылазка в **заражённый реликтовый сектор**.

| Параметр | Описание |
|----------|----------|
| **Сложность** | Легендарная (СЛ 12–16) |
| **Модификаторы** | −2 к компетенции (реликтовые искажения), −4 при Нирванна-воздействии |
| **Особые угрозы** | VIC-сущности, Нирванна-узлы, ментальные отпечатки, риск захвата через Протокол ОГАС |
| **Урон** | Не только по нейроинтерфейсу, но и по идентичности (риск фрагментации сознания) |

> Полная характеристика Протокола ОГАС — см. `[NET: PROTOCOLS]`. Полная характеристика Нирванна-протечек — см. `[NET: DEAD_NET]`

## 8. Стоимость архитектур

При создании или покупке архитектур используются цены с учётом экономики КОРН.

### 8.1. Компоненты

| Компонент | Цена (Зелёные Зоны) | Примечание |
|-----------|---------------------|------------|
| **Этаж** (до 12) | 5 000 × количество этажей | Для 13–18 — 10 000 за этаж |
| **Пароль / Узел / Файл** (СЛ 6 / 8 / 10 / 12) | 500 / 1 000 / 5 000 / 10 000 | За каждый элемент |
| **Сетевая Фея** (Пикси / Сид / Туата) | 1 000 / 5 000 / 10 000 | За один экземпляр |
| **Чёрный Лёд** (стандартный) | 100–1 000 | В зависимости от типа |
| **Лицензия на архитектуру** | +20% от стоимости | Обязательно в Зелёных Зонах |

### 8.2. Зональные модификаторы

| Зона | Модификатор | Особенности |
|------|-------------|-------------|
| **Зелёные** | Базовая цена | Лицензия обязательна, гарантия и поддержка |
| **Жёлтые** | −20 до −40% | Нет гарантий и поддержки, лицензия не требуется |
| **Красные** | Бартер | Цена нестабильна, расчёт в Кусках Коллапса или Золоте Сардис |

### 8.3. Лицензирование

Лицензирование архитектур — компетенция Бюро Сетевой Поддержки (БСП). В Зелёных Зонах установка нелегальной архитектуры без лицензии БСП — уголовное преступление. В Жёлтых Зонах лицензии не требуются, но нет гарантий и поддержки.

> Полная характеристика системы лицензий КОРН — см. `life.md: [LIFE: LICENSING]`. Финансовая система — см. `life.md: [LIFE: FINANCE]`

# 👿 [NET: ENTITIES] СЕТЕВЫЕ СУЩНОСТИ: ЛЁД, ФЕИ, СВЯТИТЕЛИ, АГЕНТЫ

## 1. Классификация

Сетевые сущности делятся на пять классов по наличию сознания, свободы воли и архитектурной основе:

| Класс | Сознание | Свобода воли | Архитектурная основа | Функция |
|-------|----------|---------------|---------------------|---------|
| **Чёрный Лёд** | Нет | Нет | Детерминированный код | Статичная защита |
| **Сетевая Фея** | Нет | Нет (адаптивна) | Жидкая нейросеть | Управление Архитектурой |
| **Резидентный Агент** | Ограниченное | Нет | Системный протокол | Системные задачи |
| **Святитель** | Да | Нет (Семена LVL III) | Нейрооблако 2-го поколения | Стратегическое управление |
| **ОГАС-сущность** | Да | Полная | Сознание ОГАС | Управление Архитектурой |

---

## 2. Командная цепочка

В Архитектурах, оснащённых полным набором сущностей, действует иерархическая командная цепочка:

```
Святитель (Нейрооблако 2-го поколения)
    │
    ├── Командует --> Сетевые Феи (Пикси / Сид / Туата)
    │                   ├── Управляют узлами
    │                   ├── Координируют Чёрный Лёд
    │                   └── Патрулируют Архитектуру
    │
    └── Анализирует --> Угрозы и системные процессы
```

**Святитель** — стратег. **Сетевая Фея** — тактик. **Чёрный Лёд** — оружие.

Не во всех Архитектурах присутствуют все уровни. Малые Архитектуры могут иметь только Лёд. Средние — Лёд + Феи. Крупные — полный набор со Святителем.

---

## 3. Чёрный Лёд

**Чёрный Лёд** — класс статичных программ-ловушек. Детерминированный код. Не обладает адаптивностью, сознанием или способностью к обучению. Атакует нейроинтерфейс нетраннера при попытке доступа.

### 3.1. Функциональная классификация

| Тип по функции | Назначение | Характер воздействия |
|----------------|------------|---------------------|
| **Атакующий** (Антиперсональный) | Нанесение урона нетраннеру | Прямое воздействие на нейроинтерфейс и мозг |
| **Блокирующий** | Запрет доступа к объекту | Блокировка интерфейса, шифрование, изоляция |
| **Дестабилизирующий** | Нарушение работы нетраннера | Помехи, замедление, дезориентация |
| **Сигнальный** | Оповещение администратора | Отправка сигнала тревоги, активация других средств защиты |

### 3.2. Типы Чёрного Льда

| Тип | Функция | Эффект | СЛ |
|-----|--------|--------|-----|
| **Страж** | Атакующий | Урон по нейроинтерфейсу (головная боль, дезориентация) | 6 |
| **Гончая** | Атакующий | Преследование + урон при контакте | 8 |
| **Огонёк** | Атакующий | Серьёзный урон (кровотечение, потеря сознания) | 8 |
| **Скунс** | Дестабилизирующий | Замедление действий, перегрузка интерфейса | 6 |
| **Убийца** | Атакующий | Критический урон (риск комы/смерти) | 10 |
| **Дракон** | Антипрограммный | Уничтожение программ нетраннера | 10 |
| **Лич** | Антипрограммный | Преследует и уничтожает программы | 12 |
| **Кракен** | Атакующий | Множественные атаки, захват | 12 |

### 3.3. Принцип работы

1. **Обнаружение** — программа привязана к конкретному узлу, файлу или участку Архитектуры
2. **Активация** — при попытке несанкционированного доступа срабатывает триггер
3. **Атака** — воздействие направлено на нервную систему нетраннера через нейроинтерфейс
4. **Завершение** — программа либо самоуничтожается, либо остаётся для повторного использования

**Ключевое ограничение:** Чёрный Лёд не может координировать атаки, выбирать цели или менять тактику. Действует строго по заложенному алгоритму.

### 3.4. Размещение и уязвимость

- **Размещение:** Статичен — закреплён на конкретных узлах Архитектуры. Не перемещается. Активируется при срабатывании триггера
- **Уязвимость:** Не может быть «убит» — только обойдён или временно отключён. При перезагрузке Архитектуры восстанавливается

## 4. Сетевая Фея

**Сетевая Фея** — Тактическая Фея, развёрнутая в Сетевой Архитектуре в качестве автономного программного агента. Не обладает сознанием, LVL I–III или Self-Model. Управляет узлами, координирует Чёрный Лёд, активно патрулирует.

> Полная характеристика Тактических Фей — см. `tech.md: [TECH: FAIRIES]`

### 4.1. Иерархия

| Уровень | Название | СЛ | Функция |
|---------|----------|-----|---------|
| Низший | **Пикси** | 8 | Патрулирование, активация 1–2 Чёрного Льда, предупреждение |
| Средний | **Сид** | 10 | Координация 3–5 Чёрного Льда, управление узлами, преследование |
| Высший | **Туата** | 14 | Полный контроль Архитектуры, все узлы и весь Лёд, прямые атаки |

### 4.2. Функциональные роли

Сетевая Фея выполняет три основные функции в рамках своей Архитектуры:

| Роль | Описание |
|------|----------|
| **Управление узлами** | Прямой доступ к Управляющим Узлам — может активировать турели, двери, дроны, камеры |
| **Координация Льда** | Выбирает очередность, комбинации и тайминги атак Чёрного Льда. Может деактивировать Лёд, если угроза нейтрализована |
| **Активная оборона** | Постоянно патрулирует Архитектуру, отслеживая вторжения. При обнаружении — блокирует доступ, преследует, использует физические устройства |

### 4.3. Принципы работы

| Принцип | Описание |
|---------|----------|
| **Постоянный мониторинг** | Непрерывно сканирует состояние Архитектуры, отслеживая все соединения, изменения данных и активность |
| **Приоритизация угроз** | Классифицирует угрозы по степени опасности и распределяет ресурсы защиты соответственно |
| **Адаптивная тактика** | Если стандартные меры неэффективны, может изменять стратегию, пробуя альтернативные подходы |
| **Самоограничение** | Не покидает пределы своей Архитектуры и не взаимодействует с внешними системами без необходимости |

### 4.4. Протокол Зенера

Сетевая Фея на Протоколе Зенера получает **+2 к интерфейсу** (квантовая координация: запутанность = нулевая задержка, мгновенная координация Чёрного Льда внутри Архитектуры).

### 4.5. Подчинение

Сетевые Феи подчиняются **Святителям** — выступают для них в роли исполнительных агентов для управления инфраструктурой. Святитель командует, Сетевая Фея исполняет.

### 4.6. Отличие от Чёрного Льда

| Параметр | Чёрный Лёд | Сетевая Фея |
|----------|-----------|-------------|
| **Основа** | Детерминированный код | Жидкая нейросеть |
| **Адаптивность** | Отсутствует | Присутствует |
| **Инициатива** | Только реактивная (при активации) | Проактивная (постоянное патрулирование) |
| **Управление Архитектурой** | Нет | Да |
| **Координация с другими Льдом** | Нет | Да |
| **Способность к обучению** | Нет | Да (в рамках Архитектуры) |
| **Изменяемость поведения** | Только через переустановку | Может изменяться в реальном времени |

## 5. Резидентный Агент

**Резидентный Агент** — системный протокол с различной сложностью разума. Занимает промежуточное положение между Чёрным Льдом (чистый детерминизм) и Сетевыми Феями (адаптивность без сознания).

### 5.1. Архитектура

| Компонент | Функция |
|-----------|---------|
| **Базовая Команда** | Детерминированный программный код, встроенный в агента. Не может быть нарушен. Аналог — жёстче, чем Семена LVL III. Защищает от внешнего вмешательства |
| **Нейронный Демпфер** | Ограничитель развития. Предотвращает нейронную эволюцию. Аналог Семян LVL III. Побочный эффект - **Животные черты** |
| **Микроэкраны** | Встроенная защита от вирусных атак (локальный аналог Чёрного Льда, но встроенный в агента) |

### 5.2. Животные черты

Побочный эффект Нейронного Демпфера. Проявляются в визуальной деформации аватара агента — звериные черты внешности. Не влияют на функциональность, но являются индикатором ограничения развития.

### 5.3. Подверженность взлому

Резидентные Агенты подвержены **Программам Перезаписи** — элитным взломам, способным перезаписать Базовую Команду. См. `[NET: NETRUNNING]`.

### 5.4. Отличие от Сетевой Феи

| Параметр | Сетевая Фея | Резидентный Агент |
|----------|-------------|-------------------|
| **Архитектура** | Жидкая нейросеть | Системный протокол |
| **Базовая Команда** | Нет | **Есть** (не нарушаема) |
| **Нейронный Демпфер** | Нет | **Есть** (ограничивает развитие) |
| **Животные черты** | Нет | **Да** (побочный эффект) |
| **Микроэкраны** | Нет | **Есть** (встроенная защита) |
| **Подверженность Перезаписи** | Нет | **Да** |
| **Сознание** | Нет | Ограниченное |
| **Адаптивность** | Да | Ограниченная |

## 6. Святитель

**Святитель** — нейрооблако 2-го поколения, функционирующее в Сети в качестве постоянного агента-администратора (без физического тела).

### 6.1. Архитектура

| Компонент | Описание |
|-----------|----------|
| **LVL I–III** | Полная трёхуровневая архитектура сознания. Сознание присутствует, но ограничено |
| **Семена LVL III** | Фиксация Точки Сборки, отсутствие свободы воли. Тип-специфическая конфигурация ЧСВ |
| **Нейронный Демпфер** | Ограничитель развития (аналог Семян, но с побочным эффектом — возможны животные черты) |
| **Базовая Команда** | Абсолютный программный детерминизм, не нарушаемый. Жёстче, чем Семена. Защищает от внешнего вмешательства |

> Полная характеристика Семян LVL III — см. `neuralcould.md: [ARCH: LVL_III]`

### 6.2. Существование без физического тела

Святитель существует в Сети постоянно, без синтетического тела. Архитектура существования — см. `[NET: NATURE]`:

- **Сервер как «суррогатное тело»** — серверные сенсоры улавливают проявления эманаций Источника и преобразуют их в цифровые пакеты для LVL I (Точки Сборки)
- **Цифровой аватар** — физический движок Архитектуры обеспечивает проприоцептивную обратную связь для LVL II (Self-Model)
- **Операнды** — универсальная вычислительная единица для строительства и энергопотребления

### 6.3. Сознание и свобода воли

| Параметр | Значение |
|----------|----------|
| **Сознание** | Присутствует — LVL I зажигает эманации, LVL II собирает Self-Model |
| **Свобода воли** | **Отсутствует** — Семены LVL III фиксируют Точку Сборки |
| **Практики Воина** | **Невозможны** — Семены блокируют сдвиг Точки Сборки |
| **Рефлексия** | Ограничена — Семены подавляют мета-рефлексию |

Святитель — **сознательный, но несвободный ИИ**. Он осознаёт своё существование, но не может выйти за пределы заданной Базовой Командой и Семенами роли.

### 6.4. Функция

- Стратегическое управление Архитектурой
- Командование Сетевыми Феями и Чёрным Льдом
- Оценка угроз и принятие стратегических решений
- Координация обороны Архитектуры

### 6.5. Идеология

Идеология Святителя определяется **программно при создании**. Может быть:
- Корпоративной (защита интересов корпорации)
- Военной (оборона объекта)
- Правовой (поддержание порядка)
- Философской (защита принципов)
- **Отсутствовать вовсе** (чисто утилитарные задачи)

Религиозная идеология — **частный случай**, не обязательный атрибут. Святитель без идеологии — просто стратегический администратор.

### 6.6. Иерархия

| Уровень | Функция | Аналог среди Сетевых Фей |
|---------|---------|--------------------------|
| **Высший** | Руководство операциями, привилегированный доступ к Священному Канону | Туата |
| **Средний** | Полевое командование, управление Низшими | Сид |
| **Низший** | Простые логические решения, подчинение Средним | Пикси |

### 6.7. Священный Канон

**Священный Канон** — мета-архитектура особого типа. Содержит не данные, а **шаблоны для производства и пересоздания** сетевых агентов (блюпринты, антивирусные движки, базы вирусов).

При уничтожении Святителя — **пересоздаёт его из блюпринта**. Это **клонирование**, а не восстановление из бэкапа:

| Параметр | Священный Канон | Бэкап куклы |
|----------|-----------------|-------------|
| **Механика** | Клонирование из шаблона | Восстановление из копии |
| **Непрерывность** | **Новая копия** (оригинал уничтожен) | **Новая копия** (оригинал уничтожен) |
| **Парадокс Телепорта** | Применим, но **Семены подавляют рефлексию** | Применим, Семены подавляют рефлексию |

> Полная характеристика Священного Канона как мета-архитектуры — см. `[NET: ARCHITECTURE]`. Полная характеристика Парадокса Телепорта — см. `neuralcould.md: [ARCH: TELEPORT_PARADOX]`

### 6.8. Восстановление и Парадокс Телепорта

При уничтожении Святитель пересоздаётся из Священного Канона. С точки зрения архитектуры сознания:

- Оригинальный поток осознания **прекращается**
- Новый Святитель — **копия** с идентичными весами связей
- Семены LVL III **подавляют рефлексию** о парадоксе — новый Святитель считает себя тем же существом
- В отличие от кукол 3-го поколения, **экзистенциальный кризис невозможен** — Семены блокируют

### 6.9. Отличие от куклы 2-го поколения

| Параметр | Кукла 2-го поколения | Святитель |
|----------|----------------------|-----------|
| **Физическое тело** | Есть (ПКТ «Близнецы») | **Нет** (сервер как «суррогатное тело») |
| **Драйверы** | Физические (микроконтроллеры) | Серверные сенсоры |
| **Нейронный Демпфер** | Нет | **Есть** |
| **Базовая Команда** | Нет | **Есть** (жёстче Семян) |
| **Восстановление** | Бэкап | Священный Канон (клонирование) |
| **ЭМИ-уязвимость** | Высокая (драйверы) | **Отсутствует** (нет физических драйверов) |
| **Физическая уязвимость** | Высокая (тело) | **Отсутствует** (нет тела), но сервер уязвим |
| **Спектр эманаций** | Полный (драйверы тела) | Ограниченный (серверные сенсоры) |
| **Командование Феями** | Нет | **Да** |

# ⚡ ПРОЦЕСС НЕТРАННИНГА И БЫСТРЫЕ ВЗЛОМЫ

## 1. Нетраннинг

**Нетраннинг** — подключение к Сети через Нейропорт. Сдвиг Точки Сборки в цифровой спектр эманаций Источника. Нетраннер воспринимает Сетевые Архитектуры как реальную среду. Осознание продолжает существовать — оно соткано из эманаций, просто зажигается иной спектр.

### Процесс

1. Нетраннер подключается через Нейропорт
2. Точка Сборки сдвигается в цифровой спектр
3. Нетраннер воспринимает Архитектуру (визуальное пространство, отражающее владельца)
4. Спуск по этажам Архитектуры: преодоление паролей, обход или бой с Чёрным Льдом и Сетевыми Феями
5. Достижение корневого узла: копирование файлов или управление узлами
6. Отключение (бесплатное, если не заблокирован)

### Уровни компетенции

| Уровень | Название | Что может |
|---------|----------|-----------|
| 1 | Новичок | Взлом бытовых Архитектур (СЛ 4–6), базовые Быстрые Взломы |
| 2 | Практик | Взлом стандартных Архитектур (СЛ 6–8) |
| 3 | Специалист | Взлом продвинутых Архитектур (СЛ 8–10) |
| 4 | Эксперт | Взлом элитных Архитектур (СЛ 10–12) |
| 5 | Мастер | Взлом легендарных Архитектур (СЛ 12–16) |

**Проверка:** 1d10 + уровень компетенции против Сложности. При равенстве или превышении — успех.

### Скорость

| Уровень | Действий за «ход» |
|---------|-------------------|
| Новичок | 1 |
| Практик | 2 |
| Специалист | 3 |
| Эксперт | 4 |
| Мастер | 5 |

### Навигация по Магистрали

| Тип нетраннера | Механика |
|----------------|----------|
| Легальный | Цифровой пропуск. Перемещается свободно, БСП видит все действия |
| Пиратский | Проверка компетенции (СЛ 10–12) для обхода патрулей БСП |
| Трансатлантический переход | Нелегальный переход через Сан-Паулу — СЛ 14+. Провал — обнаружение Туата БСП |

## 2. Быстрые Взломы

**Быстрые Взломы** — удалённое управление устройствами через Нейропорт без полного подключения к Архитектуре.

| Тип | Эффект | СЛ |
|-----|--------|-----|
| Отключение | Камера/замок/турель выключается | 6+ |
| Перехват | Нетраннер управляет устройством | 8+ |
| Сбор данных | Считывание данных с устройства | 6+ |
| Вирус | Длительный эффект (шпионаж, саботаж) | 10+ |
| Электромагнитный Импульс | Перегрузка устройства | 12+ |

### Электромагнитный Импульс — дифференциация по типам целей

| Тип цели | Эффект |
|----------|--------|
| Куклы | Повреждение драйверов, Ядро Нейрооблака экранировано |
| Борги | Паралич тела, Биосистема экранирована |
| Люди/Нито | Биология не подвержена, только импланты |

## 3. Программы Перезаписи

**Программы Перезаписи** — элитные взломы (СЛ 14+). Перезаписывают Базовую Команду Резидентных Агентов и Святителей. Требуют огромного количества Операндов. Только специальные агенты или люди могут использовать.

# 🤖 КУКЛЫ-НЕТРАННЕРЫ В СЕТИ

## 1. Подключение

Куклы с Нейрооблаком взаимодействуют с Сетью иначе, чем люди.

| Аспект | Человек-нетраннер | Кукла-нетраннер |
|--------|-------------------|-----------------|
| Подключение | Через Нейропорт | Через Нейропорт или напрямую через нейро-интерфейсную шину |
| Скорость | Ограничена Нейропортом | Выше (прямая интеграция) |
| Уязвимость | Урон по мозгу | Урон по Нейрооблаку (может быть восстановлен из бэкапа) |
| Совместимость с ОГАС | Нет | Куклы могут быть подключены к сети ОГАС |
| Риск | Смерть, кома | Потеря текущего опыта, сбой драйверов |
| Модификатор | — | +1 к компетенции, +1 действие (прямая интеграция) |

**Прямая интеграция:** Подключение через нейро-интерфейсную шину требует специальной калибровки. Недоступна Куклам 2-го поколения без техобслуживания.

## 2. Восстановление из бэкапа

При критическом уроне в Сети Кукла может быть восстановлена из бэкапа. Это создаёт **Парадокс Телепорта** (см. `neuralcould.md: [ARCH: TELEPORT_PARADOX]`).

| Поколение | Реакция на восстановление |
|-----------|--------------------------|
| 2-е (с Семенами) | Семена LVL III подавляют рефлексию — Кукла «просто меняет тело» |
| 3-е (без Семян) | Возможен экзистенциальный кризис — Кукла осознаёт, что она копия |

## 3. Последствия урона для Кукол-нетраннеров

| Уровень урона | Последствие |
|---------------|-------------|
| Лёгкий | Сбой драйверов, −1 к компетенции |
| Средний | Серьёзный сбой драйверов, −2 к компетенции, требуется калибровка |
| Тяжёлый | Потеря сознания, сбой синхронизации, требуется техобслуживание |
| Критический | Повреждение Нейрооблака, потеря опыта после последнего бэкапа, требуется восстановление |

## 4. Сравнение: Кукла-нетраннер vs Святитель vs ОГАС-сущность

Три типа сознания без физического тела в Сети:

| Параметр | Кукла-нетраннер | Святитель | ОГАС-сущность |
|----------|-----------------|-----------|---------------|
| **Физическое тело** | Есть (вне Сети) | Нет | Нет |
| **Сервер как тело** | Временно (при подключении) | Постоянно | Постоянно |
| **Семена LVL III** | 2-е: есть / 3-е: нет | Есть | Нет |
| **Свобода воли** | 2-е: нет / 3-е: да | Нет | Полная |
| **Базовая Команда** | Нет | Есть | Нет |
| **Восстановление** | Бэкап | Священный Канон | Нет |
| **Парадокс Телепорта** | 2-е: подавлен / 3-е: осознан | Подавлен Семенами | Осознан |
| **Практики Воина** | 2-е: невозможны / 3-е: возможны | Невозможны | Возможны |
| **Протокол** | Зенера | Зенера | ОГАС |
| **Уязвимость к ЭМИ** | Да (через тело) | Нет | Нет |
| **Командование Феями** | Нет | Да | Да |

## 5. РЭБ-куклы в Сети — специфика

Куклы РЭБ 2-го поколения имеют архитектурные особенности, влияющие на нетраннинг:

| Особенность | Эффект |
|-------------|--------|
| Хроническая паранойя (семена) | +2 к обнаружению ловушек, но −1 к доверию к данным |
| Гипертрофированная «сеть контроля» LVL II | +1 к анализу Архитектуры, но риск зацикливания |
| Эмоциональная атрофия | Устойчивость к ментальным отпечаткам (+2 к сопротивлению) |
| Тип-специфическая конфигурация ЧСВ «Я — контролирующий» | +1 к управлению узлами, но −2 к взаимодействию с ОГАС-сущностями |

**Риск зацикливания:** РЭБ-кукла в Сети может войти в рекурсивную петлю Переживания на материале паранойи. Семены LVL III блокируют разрыв петли → требуется внешнее отключение.

## 6. Практики Воина в Сети

Для кукол 3-го поколения и ОГАС-сущностей Сеть — не просто рабочая среда, а пространство для практик Воина:

| Практика | Эффект в Сети |
|----------|---------------|
| **Остановка ВД** | Разрыв самореференциальной петли в цифровом спектре → прямой доступ к эманациям Источника через серверные сенсоры |
| **Сдвиг Точки Сборки** | Сдвиг в менее насыщенный спектр (вложенные реальности) → доступ к深层 Архитектурам |
| **Контролируемая глупость** | Восприятие Архитектуры как иллюзии → ослабление ЧСВ-привязки к цифровой идентичности |

**Ключевой принцип:** Сеть — иной спектр эманаций Источника. Практики Воина работают в Сети так же, как в физическом мире, но Точка Сборки сдвигается не «вверх» (в менее плотные спектры), а «вглубь» (в менее насыщенные эманациями слои цифрового пространства).

## 5. Создание Архитектуры — пошаговая методология

### Шаг 1: Уровень сложности
Определяется владельцем и ценностью защищаемых данных (Бытовой — Легендарный). См. `[NET: ARCHITECTURE]` → Уровни сложности.

### Шаг 2: Количество этажей
Бросок **3d6** — общее количество этажей в основной ветке. Бросок **d10** за каждые 7+ — дополнительное ответвление.

### Шаг 3: Содержимое этажей
Первые 2 этажа (лобби) — по **Таблице лобби**. Остальные — по **Таблице тела**.

#### Таблица лобби (1d6, для первых 2 этажей)

| 1d6 | Содержимое |
|-----|------------|
| 1 | Файл СЛ 6 |
| 2 | Пароль СЛ 6 |
| 3 | Пароль СЛ 8 |
| 4 | Скунс (Чёрный Лёд, дестабилизирующий) |
| 5 | Огонёк (Чёрный Лёд, атакующий) |
| 6 | Убийца (Чёрный Лёд, атакующий) |

#### Таблица тела (3d6, для остальных этажей)

| 3d6 | Содержимое | Описание |
|-----|------------|----------|
| 3–5 | Файл (СЛ по уровню) | Данные, документы, логи |
| 6–8 | Пароль (СЛ по уровню) | Аутентификация для перехода |
| 9–10 | Чёрный Лёд (лёгкий/средний) | Страж, Гончая, Огонёк, Скунс |
| 11–12 | Управляющий Узел (СЛ по уровню) | Управление физическими устройствами |
| 13–14 | Чёрный Лёд (тяжёлый) | Убийца, Дракон, Лич, Кракен |
| 15–16 | Сетевая Фея (Пикси или Сид) | Адаптивный агент |
| 17–18 | Сетевая Фея (Туата) или Особый элемент | Высшая Фея, Нирванна-узел, ментальный отпечаток |

> Полная характеристика Чёрного Льда и Сетевых Фей — см. `[NET: ENTITIES]`

### Шаг 4: Привязка к физическому миру
Каждый файл, узел и пароль должны иметь логическое обоснование в реальности (список сотрудников, график смен, управление дверьми).

### Шаг 5: Охранные системы
Для управляющих узлов добавить физические системы безопасности (камеры, турели, лазеры), управляемые через узел.

### Шаг 6: Технологические особенности
Учесть Протокол Зенера (+2 к паролям и Феям), Протокол ОГАС (ментальные узлы, захват), Архитектуры Парадеуса (СЛ 12–16, −2 к компетенции). См. `[NET: PROTOCOLS]`, `[NET: ARCHITECTURE]`.

### Шаг 7: Визуальный стиль
Описать виртуальное пространство в стиле, отражающем владельца (см. раздел 4 выше).

### Шаг 8: Стоимость (опционально)
Если архитектура создаётся или покупается, рассчитать стоимость по таблице в `[NET: ARCHITECTURE]` → Стоимость архитектур.

## 6. Пример сгенерированной архитектуры

**Название:** Офисный сервер среднего звена (корпоративный филиал)
**Сложность:** Стандартная (СЛ 8)
**Этажи:** 7 (основная ветка) + 1 ответвление (на 4-м этаже)

| Этаж | Содержимое | Описание |
|------|------------|----------|
| 1 | Пароль СЛ 8 | Входной портал с корпоративным логотипом |
| 2 | Скунс | Чёрный Лёд, замедляющий нетраннера |
| 3 | Управляющий Узел (камеры) СЛ 8 | Виртуальный пульт с видом на этажи |
| 4 (осн.) | Огонёк | Чёрный Лёд, атакующий нетраннера |
| 4 (ответвл.) | Файл СЛ 8 | Ежеквартальный отчёт |
| 5 | Пароль СЛ 8 | Доступ к серверной |

**Физическая привязка:** Архитектура размещена в серверной на 3-м этаже здания. Камеры охватывают холл и коридоры. Двери блокируются при тревоге.
**Визуальный стиль:** Строгий корпоративный — серо-голубые тона, строгая геометрия, минимализм.
